1. Introduction & Overview

KillTheHost is an all-in-one local development platform that bridges the gap between localhost and the live web. It bundles seven open-source, single-file Python tools into a unified browser-based workflow — letting you run PHP sites, manage databases, host your own email, deploy Docker stacks, manage Node.js apps, lock everything down with 24/7 security monitoring, and give every local project a real domain name with HTTPS — all from one place.

Version 1.5 introduced SEC-MNGR — a security manager and threat dashboard that watches every KillTheHost manager, bans attacking IPs automatically, and monitors the host around the clock.

Version 1.6 introduces LDOMAIN-3NGIN3 — a local domain and reverse proxy manager that gives every local project a real .local-style domain name, HTTPS via a self-signed local CA, and a full HTTP/HTTPS reverse proxy without any external tools.

Tool Version Purpose
[L] Launcher v1.6 Unified browser UI — start, stop, monitor all tools
[PHP] PHP-MNGR v2.5 Local & public PHP project manager via Docker
[DB] DB-3NGIN3 v1.2 Database service manager — PostgreSQL, MySQL, MariaDB, Redis, MongoDB
[MAIL] MAIL-SRVR v1.0 Self-hosted email server with full browser mail client
[STAX] STAX-MNGR v1.0 Docker stack manager — one-click pre-configured stacks
[NODE] NODE-MNGR v1.0 Node.js app manager — React, Next.js, Vite, Express
[SEC] SEC-MNGR New v1.5 v1.0 Security manager — unified access logs, IP bans, Fail2Ban rules, 24/7 monitoring
[DNS] LDOMAIN-3NGIN3 New v1.6 v1.0 Local domain & reverse proxy manager — DNS, TLS, HTTP/HTTPS proxy, hosts-file adapter

9. SEC-MNGR — Security Manager New in v1.5

SEC-MNGR is the security layer for the whole KillTheHost stack. It is a single Python 3.8+ file (stdlib-only) with an embedded browser dashboard. Start it from the launcher, or run directly:

python3 "Launcher/assets/main/SEC-MNGR v1.0/sec_mngr.py"
# → http://127.0.0.1:8080

python3 "Launcher/assets/main/SEC-MNGR v1.0/sec_mngr.py" \
        --host 127.0.0.1 --port 8080 --no-browser
By default the panel binds to 127.0.0.1 — it has no login. For remote access use an SSH tunnel: ssh -L 8080:127.0.0.1:8080 user@vps

Dashboard Tabs

TabWhat it shows
OverviewThreat level, posture score, service health, 24h traffic chart, event timeline
Access LogsUnified access log — search, filter, export (CSV/JSON)
IP ManagerIP intelligence, manual bans, allowlist, firewall export
Detection RulesFail2Ban-style rules — thresholds, windows, durations
MonitoringService UP/DOWN, CPU/mem/disk, Docker, UFW, port scan
System HealthLatest health snapshot and log sources
SettingsRetention, intervals, detection mode, known ports

What SEC-MNGR Watches

SEC-MNGR tails the log files of every KillTheHost manager: ~/.phpmngr/, ~/.db3ngin3/, ~/.mailsrvr/, ~/.staxmngr/, ~/.nodemngr/, ~/.killthehost/launcher.log, and (from v1.6) ~/.ldomain3ngin3/access_logs.jsonl. It also reads Docker logs from manager containers.

Securing Your Stack with SEC-MNGR

  1. Start SEC-MNGR from the launcher and open http://127.0.0.1:8080
  2. In IP Manager, add your own IP to the Allowlist first — so you never lock yourself out
  3. Review Detection Rules thresholds; set Settings → detection mode to monitor to only log while tuning
  4. Ban an IP or CIDR range from IP Manager → Ban an IP / CIDR
  5. For real firewall bans, run with root or passwordless sudo and have UFW/iptables installed
  6. Use Access Logs to search traffic across every service and export to CSV/JSON

Detection Rules (Defaults)

RuleTriggerBan
AUTH_FAIL5 auth failures in 10 min1 h
RATE_FLOOD100 HTTP requests in 60 s30 min
PATH_PROBE10 × 404 in 5 min2 h
MALFORMED20 malformed requests in 10 min1 h
MAIL_FAIL3 SMTP/IMAP auth failures in 5 min4 h
DB_FAIL5 database auth failures in 10 min2 h
REPEAT_OFFENDERIP banned 3 timespermanent

Enforcement Model

  1. UFW (ufw prepend deny from <ip>) if installed and active
  2. iptables / ip6tables (plus DOCKER-USER chain) otherwise
  3. HTTP-level blocking always applies — banned IPs receive 403

Firewall commands need root or passwordless sudo -n. Without them, SEC-MNGR does not fail — it logs the exact commands to run and relies on HTTP-level blocking.

10. LDOMAIN-3NGIN3 — Local Domain & Reverse Proxy Manager New in v1.6

LDOMAIN-3NGIN3 gives every local project a real domain name (e.g. app.dev.local), HTTPS via a self-signed local CA, and a full HTTP/HTTPS reverse proxy — all without touching a public DNS provider, installing nginx, or running external tools. It is a single Python 3.8+ file (stdlib only) with an embedded browser dashboard.

Start it from the launcher, or run directly:

python3 "Launcher/assets/main/LDOMAIN-3NGIN3 v1.0/ldomain3ngin3.py"
# → http://localhost:8181

python3 "Launcher/assets/main/LDOMAIN-3NGIN3 v1.0/ldomain3ngin3.py" \
        --port 8181 --no-browser
Binding the reverse proxy to :80 and :443 requires root or passwordless sudo. Without it, LDOMAIN-3NGIN3 falls back to :8180 (HTTP) and :8143 (HTTPS) automatically.

How It Works

Browser / curl ──► https://app.dev.local │ LDOMAIN-3NGIN3 (:443 / :8143) TLS termination │ reverse proxy ──► banned? → 403 (SEC-MNGR blocklist) │ http://localhost:4280 (your PHP site, Node.js app, etc.) LAN device ──► DNS query ──► LDOMAIN-3NGIN3 (:5353) ──► A record response hosts file ──► 127.0.0.1 (single-machine, no DNS server needed)

Features

FeatureDetails
Local DNS resolverPure-Python UDP DNS on :5353 — A-record responses for registered domains
Reverse proxyHTTP :80/:8180 and HTTPS :443/:8143 — raw TCP sockets, WebSocket-capable
TLS via local CARoot CA + per-domain certs with SAN extensions, generated with openssl
Hosts-file adapterWrites 127.0.0.1 entries to /etc/hosts inside managed block markers
SEC-MNGR integrationWrites access logs in SEC-MNGR JSONL format; enforces SEC-MNGR IP bans before forwarding
Per-domain health checksBackground TCP port checks every 60 s — UP/DOWN status in dashboard
Integration APIPOST /api/integrate — other managers can register/remove domains programmatically
Browser dashboardDark-theme UI at http://localhost:8181

Setting Up a Local Domain

  1. Start LDOMAIN-3NGIN3 from the launcher and open http://localhost:8181
  2. Click + Add Domain and enter a domain name (e.g. myapp.dev.local) and the upstream host/port (e.g. localhost:4280)
  3. Enable TLS to get HTTPS; enable Hosts File to write to /etc/hosts
  4. Install the root CA once in your browser or OS (see below)
  5. Open https://myapp.dev.local in your browser — it routes to localhost:4280 with a trusted certificate

CA Installation (One-Time Per Device)

Linux (system-wide)

sudo cp ~/.ldomain3ngin3/ca/ca.crt /usr/local/share/ca-certificates/ldomain3ngin3.crt
sudo update-ca-certificates

macOS

sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/.ldomain3ngin3/ca/ca.crt

Windows

certutil -addstore -f "ROOT" "$env:USERPROFILE\.ldomain3ngin3\ca\ca.crt"

Firefox

Preferences → Privacy & Security → View Certificates → Authorities → Import → select ca.crt → check "Trust this CA to identify websites".

iOS

AirDrop or email ca.crt → Settings → General → VPN & Device Management → install → Settings → General → About → Certificate Trust Settings → enable.

Android

Settings → Security → Install from storage → select ca.crt.

SEC-MNGR Integration

LDOMAIN-3NGIN3 automatically integrates with SEC-MNGR with no configuration required:

  • Access logs: Every proxied request is logged to ~/.ldomain3ngin3/access_logs.jsonl in SEC-MNGR's unified JSONL format (ts, timestamp, ip, method, path, status, user_agent, service, event_type, source, detail). SEC-MNGR picks these up automatically from v1.6 onwards.
  • Blocklist enforcement: LDOMAIN-3NGIN3 reads ~/.secmngr/blocklist.txt every 30 seconds. Any IP on the blocklist receives a 403 Forbidden before the request is forwarded to the upstream.

11. Domain Sync & Cloudflare Tunnels

KillTheHost connects your local services to real domains via Namecheap DNS sync and Cloudflare Tunnels — no port forwarding, no router config, works on CGNAT connections.

Connecting a Domain

  1. Whitelist your public IP in Namecheap API settings
  2. Create a scoped Cloudflare API token with: Account → Cloudflare Tunnel (Edit & Read), Zone → Zone (Read), Zone → DNS (Edit & Read)
  3. Open PHP-MNGR → Settings → Cloudflare, paste your API token and save
  4. Open PHP-MNGR → Settings → Namecheap, enter your API key and username
  5. Go to Domains & Tunnels, select a domain, map it to your local service, and apply

Going Live with Cloudflare

  1. Go to Domains & Tunnels and click Tunnel Site on any domain
  2. Select your PHP site from the dropdown and hit Tunnel Now
  3. Your site is now reachable at your real domain
Cloudflare Tunnels work on CGNAT connections (e.g. T-Mobile 5G home internet) where traditional port forwarding is impossible.

14. FAQ & Common Issues

Docker permission denied on Linux

sudo usermod -aG docker $USER
# Log out and back in

Port already in use

lsof -i :PORT
kill -9 PID

Cloudflare tunnel not connecting

  • Ensure your Cloudflare API token has correct permissions (Tunnel Edit, DNS Edit, Zone Read)
  • Check that cloudflared is installed and in your PATH
  • Verify the domain is active in your Cloudflare account

Email not delivering (Live mode)

  • Confirm outbound port 25 is open on your VPS
  • Run the deliverability checklist in MAIL-SRVR → Settings
  • Ensure DKIM has been provisioned (wait 60s after starting the server)
  • Check SPF and DMARC records are published in Cloudflare DNS

NODE-MNGR app won't start

  • Ensure nvm is installed and accessible in your shell — run nvm ls to check versions
  • Verify your project has a valid package.json with a start script
  • Check the Logs tab in NODE-MNGR for the full error output

LDOMAIN-3NGIN3: browser shows "Your connection is not private"

  • The root CA has not been installed in this browser/OS yet. Follow the CA Installation steps in Chapter 10.
  • After installing, restart the browser and try again.

LDOMAIN-3NGIN3: reverse proxy returns 502 Bad Gateway

  • The upstream service (e.g. localhost:4280) is not running. Start it from the Launcher first.
  • Check the health status in the LDOMAIN-3NGIN3 dashboard — a red indicator means the upstream is down.

LDOMAIN-3NGIN3: DNS not resolving on LAN device

  • On the LAN device, set the DNS server to your machine's LAN IP (e.g. 192.168.1.x) port 5353.
  • Alternatively, enable the Hosts File option for single-machine resolution without a DNS server.

LDOMAIN-3NGIN3: :80 or :443 already in use

LDOMAIN-3NGIN3 automatically falls back to :8180 and :8143 when :80/:443 are unavailable. Use those ports in your browser, or stop whatever is holding :80/:443 first.

Services don't restart after reboot

docker update --restart unless-stopped <site-name>

systemd service (Linux):

# Save as ~/.config/systemd/user/killthehost.service
[Unit]
Description=KillTheHost Launcher

[Service]
ExecStart=/bin/sh /path/to/KillTheHost/launch.sh
WorkingDirectory=/path/to/KillTheHost
Restart=on-failure

[Install]
WantedBy=default.target
systemctl --user enable --now killthehost
